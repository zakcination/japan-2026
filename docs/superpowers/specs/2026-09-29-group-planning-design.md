# Групповое планирование: имя + PIN, «я с вами», задачи на покупку билетов

**Статус:** черновик на согласование владельцем (Мирас). Интервью — 29.09.2026. Реализация не начата.
**Связано:** `docs/superpowers/specs/2026-09-29-today-apple-redesign-design.md` (текущее приложение «Сегодня»).

## 1. Цель

Мирас и Айкош — хозяева поездки. Сания, Аманжан и Шахи (визы в процессе, билеты не куплены) планируют вместе
с ними со своих телефонов: видят план с датами и временем, отмечают, к чему присоединяются, и получают ровно
те билеты, которые им нужно купить, — где, когда и как.

**Успех:** Сания открывает ссылку, выбирает своё имя, задаёт PIN, нажимает «Я с вами: Кавагутико 18.10» —
и во вкладке «Дела» у неё появляются «Купить: автобус Keio 06:45 — highwaybus.com (места рядом с нашими)» и
«Купить: автобус Fujikyu 17:00 → Мисима», с сайтом, датой открытия продаж, сроком и ценой. Хозяева видят,
что Сания едет 18-го.

## 2. Решения владельца (интервью 29.09)

| Вопрос | Решение |
|---|---|
| Порядок | Сначала групповое планирование + задачи (B+C); объединение карты (A) — отдельным проектом после |
| Права гостей | Смотрят план, присоединяются, **предлагают изменения**; хозяева одобряют |
| Вход | Хозяева заводят имена; человек выбирает имя и задаёт **4-значный PIN**; хозяева сбрасывают забытый PIN |
| Общие данные | **Supabase** (бесплатный план, без карты — проверить при регистрации); он — дом плана |
| Единица участия | Часть поездки (минимум) → день → отдельный пункт; часть включает всё сразу; внутри можно **отписаться** от занятий |
| Кто покупает | **Каждый сам**; задачи с полным рецептом; хозяева могут показать свою бронь |
| Старый трекер | Задачи из артефакта claude.ai переезжают в приложение; артефакт выводится из работы |
| Где в интерфейсе | Вкладка «Брони» → **«Дела»**; присоединение — на «День» |
| Видно группе | Кто куда едет; **траты** (для статистики). Не видно: прогресс задач, личные отметки |
| Уведомления | Хозяевам — новые участия и предложения; гостям — изменения плана и решения; всем — сроки покупки |
| Билеты | **PDF/картинка или ссылка** (прежде всего highwaybus.com и Booking.com), приватно по умолчанию, «показать группе» по выбору |

## 3. Этапы

1. **Этап 1 — к ~06.10** (чтобы успеть купить билеты): Supabase, имена + PIN, план в Supabase, части/дни/пункты
   с участием и отписками, «Дела» с рецептами покупки, билеты-файлы и ссылки (приватные и общие), импорт старых
   задач, офлайн-очередь.
2. **Этап 2 — к ~10.10:** предложения изменений и одобрение; уведомления (Web Push).
3. **Этап 3 — к ~14.10:** общие траты и статистика группы на «Итогах».
4. **Потом:** проект A — объединение карты (отдельная спецификация).

Каждый этап выпускается сам по себе; без Supabase (или если он недоступен) приложение работает как сейчас.

## 4. Роли и вход

- **Участники** — таблица `members`: имя, роль `host|guest`, хеш PIN. Хозяева (Мирас, Айкош) заводят гостей в ⚙.
- **Вход без паролей:** при первом открытии `?trip=miras-aikosh` → «Кто вы?» (кнопки с именами) → «Придумайте PIN»
  (первый раз) или «Введите PIN». Телефон получает анонимную сессию Supabase (`signInAnonymously`), а серверная
  функция `claim_member(member_id, pin)` проверяет PIN (bcrypt, `pgcrypto`) и привязывает эту сессию к участнику.
  Старая привязка того же участника на другом устройстве остаётся (телефон + iPad) — до 3 устройств на человека.
- **Ограничения:** 5 неверных PIN подряд — пауза 15 минут на участника (в БД). Анонимный вход у Supabase ограничен
  30 запросами в час с одного IP; CAPTCHA (Turnstile) не включаем на этапе 1 — в группе 5 человек и список имён
  закрыт; включим, если появится мусор.
- **Сброс PIN:** хозяин в ⚙ → «Сбросить PIN» → участник задаёт новый при следующем входе.
- **Потеря телефона/очистка Safari:** сессия пропадает; человек снова выбирает имя и вводит PIN.
- **Без входа** (просто открыл ссылку, не выбрал имя) — приложение работает как сейчас: план только для чтения.

## 5. Данные (Supabase, Postgres)

Регион проекта — Токио (`ap-northeast-1`). Все таблицы с RLS; в коде страницы — только URL проекта и публичный
`anon`-ключ (так задумано Supabase; защита — политики RLS).

| Таблица | Что хранит | Кто читает | Кто пишет |
|---|---|---|---|
| `trips` | id (`miras-aikosh`), название | участники | хозяева |
| `members` | id, trip, имя, роль, `pin_hash`, `fails`, `locked_until` | участники (без `pin_hash`) | хозяева; PIN — только функцией |
| `member_devices` | `auth.uid()` → member | сам | функция `claim_member` |
| `plan` | один документ поездки (JSON как `trips/*.json`) + `version` | участники | хозяева (проверка `version`) |
| `parts` | id, название, дни, пункты (или «все пункты этих дней») | участники | хозяева |
| `joins` | member, scope (`part|day|stop`), scope_id, `in|out` | участники | сам участник |
| `recipes` | booking id → что, сайт, открытие продаж, срок, цена, советы, данные брони хозяев | участники | хозяева |
| `tasks` | задачи вне рецептов (импорт, ручные): текст, кому (member/все), срок, ссылка | участники | хозяева; свои — сам |
| `task_state` | member, task/booking, `done`, дата | **только сам** | сам |
| `attachments` | member, booking, `kind file|link`, url/путь, сайт, `shared` | сам; `shared` — все участники | сам |
| `spend` (этап 3) | member, день, сумма ¥ | участники | сам |
| `proposals` (этап 2) | автор, что меняется (JSON-патч), комментарий, статус | участники | автор создаёт; хозяева решают |
| `push_subs` (этап 2) | подписка Web Push устройства | — | сам |

**Файлы билетов** — приватный bucket Storage `tickets/<member>/<booking>/<uuid>`: читает владелец; при `shared` —
все участники поездки (политика по таблице `attachments`). Файлы также кэшируются в IndexedDB на телефоне
(офлайн, как сейчас). Лимит бесплатного плана — 1 ГБ; PDF билетов — десятки КБ.

**Участие — как вычисляется:** для пары (участник, пункт) побеждает самое конкретное правило: пункт > день > часть;
нет правила — «не едет». Хозяева по умолчанию «едут» на всё. «Без меня» на пункте внутри принятой части — `out`.

**Части нашей поездки (стартовые, хозяева правят):** «Прилёт, Токио» 17.10 · «Фудзи / Кавагутико» 18.10 (до автобуса
в Мисиму) · «Киото» 18.10 вечер – 20.10 · «Нагоя и дзюдо» 20–22.10 · «Токио» 22–27.10 (внутри — Disney 24.10,
Shibuya Sky 25.10, teamLab 26.10 как отдельные пункты с отпиской).

## 6. Задачи на покупку («Дела»)

Задача появляется у участника, если он «едет» хотя бы на один пункт, связанный с бронью (`bk`), и у брони
есть рецепт. Отписка от пункта убирает задачу (если купленной отметки ещё нет; если есть — задача остаётся
с пометкой «вы отписались — сдайте/перенесите билет»).

**Рецепт (карточка задачи):**
- что купить: маршрут, дата, время, класс/тип;
- кнопка официального сайта; когда открываются продажи (с часовым поясом: «11.10 00:00 по Японии = 10.10 20:00
  по Алматы»); «купить до»;
- цена на человека (¥ + ₸);
- советы («выходить на Kawaguchiko Sta., это не конечная»);
- **бронь хозяев** — текстом («автобус 1431, 06:45, места такие-то — возьмите рядом») и, по желанию, их общий
  файл/ссылка (см. §7). Эти данные (места, номера) хранятся **только в Supabase** (`recipes.host_ref`), видны
  только участникам и никогда не попадают в репозиторий;
- «Куплено» (личная отметка) и «Прикрепить билет».

Сортировка «Дел»: сначала «продажи уже открыты и срок близко», затем «скоро открываются», затем остальное.
Задачи из старого трекера (артефакт claude.ai, коллекция `tasks`) импортируются один раз: общие → «всем»,
личные → конкретному участнику; закрытые не переносятся.

Стартовые рецепты — в приложении А.

## 7. Билеты: файлы и ссылки

- **Прикрепить:** PDF, картинка **или ссылка**. Ссылки только `https://`; сайт распознаётся по домену:
  `highwaybus.com` → «Highway Bus», `booking.com` → «Booking.com», `smart-ex.jp` → «Smart EX», иначе — домен.
  Кнопка «Открыть бронь». К одной брони — несколько вложений (ссылка Booking.com + PDF подтверждения).
- **Приватно по умолчанию.** Переключатель «Показать группе» делает вложение видимым участникам поездки.
  Для ссылок перед включением — одно предупреждение: «Ссылка на бронь часто работает как ключ: по ней можно
  открыть и иногда отменить бронь. Лучше покажите PDF без QR или данные текстом».
- **Никогда** не попадают в `trips/*.json`, репозиторий или публичные страницы.
- Показ — как сейчас: картинка/PDF на весь экран, экран не гаснет; ссылка открывается в Safari.
- Без входа (без Supabase) — работает как сейчас: файлы только на этом телефоне; ссылки тоже только локально.

## 8. Экраны

- **Вход:** лист «Кто вы?» — имена крупными кнопками → PIN (4 цифры, `inputmode=numeric`, автоотправка).
  Под именами — «Просто посмотреть» (без входа).
- **«День»:** над списком — чип части («Фудзи / Кавагутико · едут: М А С») и кнопка «Я с вами на весь день»;
  у каждого пункта — маленькие аватары едущих; в листе пункта — «Я еду» / «Без меня». Хозяин видит, кто отписался.
- **Лист части** (тап по чипу): дни и пункты части, «Я с вами на всю часть», список участников.
- **«Дела»** (бывшие «Брони»): «Мне купить» (рецепты), «Мои билеты» (вложения), «Сделать» (импортированные и ручные
  задачи), для хозяев — «Группа» (кто куда едет; этап 2 — входящие предложения).
- **⚙:** «Вы вошли как Сания · выйти»; для хозяев — участники (добавить, сбросить PIN), статус синхронизации
  («синхронизировано 2 мин назад» / «нет сети, изменения ждут отправки»), подсказка, если бесплатный проект
  Supabase «уснул» после недели без активности.
- **Этап 2:** в листе пункта — «Предложить изменение» (время, новый пункт, убрать, комментарий); у хозяев —
  «Предложения» с «Принять/Отклонить»; принятое меняет план у всех.
- **Этап 3:** на «Итогах» — траты группы по дням и по людям (каждый видит суммы всех).

## 9. Синхронизация и офлайн

- **Клиент:** официальная `supabase-js` (MIT), закреплённая версия, **встроена в страницу при сборке**
  (CSP разрешает только свои скрипты). CSP `connect-src` дополняется `https://<проект>.supabase.co` и
  `wss://<проект>.supabase.co`.
- **Чтение:** при открытии и по Realtime-событиям; последняя копия плана, частей, участий, рецептов — в
  `localStorage` (как сейчас офлайн-копия поездки). Без сети — работаем с копией, в ⚙ видно «версия от …».
- **Запись:** оптимистично на экране + очередь `outbox` в `localStorage`; отправка при сети; повтор с паузой.
  Участия и отметки — «последняя запись побеждает» (они у каждого свои). План — только хозяева, с проверкой
  `version`: при конфликте «План изменился — показать изменения / перезаписать».
- **Переход:** `trips/miras-aikosh.json` из репозитория — стартовое наполнение Supabase (скрипт миграции) и
  запасная копия, если Supabase недоступен. Местные правки хозяев в `localStorage` (как сейчас) при первом входе
  предлагается отправить в Supabase.
- Шаблон (`?trip=template`) и чужие поездки — без Supabase, как сейчас.

## 10. Уведомления (этап 2)

Web Push (стандарт, ключи VAPID) из Edge Function Supabase (`npm:web-push`); на iPhone — только когда приложение
установлено на экран «Домой» (iOS 16.4+), разрешение спрашивается кнопкой в ⚙. События: новое участие/отписка и
новое предложение → хозяевам; изменение плана и решение по предложению → затронутым гостям; сроки покупки →
ежедневная проверка (`pg_cron`) за 3 дня и в день открытия продаж.

## 11. Безопасность и приватность

- RLS на всех таблицах; политики проверены тестом с тремя анонимными сессиями (хозяин, гость, чужой).
- PIN: только хеш bcrypt, проверка на сервере, блокировка после 5 ошибок; PIN не хранится на телефоне.
- Чужой (без PIN) через ссылку видит только то же, что и сейчас: публичный план из репозитория.
- Вложения: приватный bucket, подписанные ссылки на 10 минут; ссылки на брони — предупреждение перед «Показать
  группе»; всё — вне репозитория.
- Вводимые тексты (предложения, задачи, имена) выводятся только через экранирование; ссылки — только `https:`.
- Секретов в репозитории нет: `anon`-ключ публичен по замыслу; `service_role`-ключ и ключи VAPID — только в
  настройках Supabase.

## 12. Тесты

- **Логика** (без сети): вычисление участия (пункт > день > часть, отписки), выбор задач по участию, сортировка
  «Дел», распознавание сайтов ссылок, очередь `outbox`.
- **Интерфейс** (Playwright): слой `Backend` с двумя реализациями — `SupabaseBackend` и `MemoryBackend`
  (тестовый http-сервер с общим JSON). Сценарии на нескольких «телефонах» одновременно: хозяин заводит Санию →
  Сания входит с PIN → «Я с вами: Кавагутико» → у неё две задачи → хозяин видит её аватар; отписка от катера;
  офлайн: действие уходит в очередь и отправляется после сети; неверный PIN 5 раз → пауза.
- **RLS** — скрипт против настоящего проекта (запускается вручную после миграции): гость не пишет план, не читает
  чужие отметки и приватные вложения; чужая сессия не читает участников.
- Все нынешние тесты (83) остаются зелёными; ревью безопасности и кода перед выпуском каждого этапа.

## 14. Риски и открытые вопросы

- Бесплатный проект засыпает после недели без активности — будим кнопкой в панели Supabase; во время поездки
  не заснёт. В ⚙ — подсказка, где нажать.
- Требование карты при регистрации Supabase не подтверждено документацией — проверяется на шаге 1.
- Веб-пуш на iPhone работает только в установленном приложении; в Safari-вкладке — только значки внутри.
- Отели: «каждый покупает сам» — значит, каждой паре нужен свой номер; хозяева выбирают отель и делятся ссылкой
  на объявление (не на свою бронь).
- Рецепты — по состоянию на 29.09; пункты с «проверить» уточняются перед выпуском этапа 1.
